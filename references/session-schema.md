# Session 数据结构（gen_review.py 输入）

`gen_review.py` 的 `--session` 参数接收一个 JSON 文件，描述一场面试的完整复盘数据。

## 完整字段

```jsonc
{
  // —— 基本信息 ——
  "candidate": "张三",      // 候选人姓名
  "round": 1,                        // 第几场（1=一面）
  "company": "百度",                 // 公司
  "position": "产品经理",            // 岗位
  "date": "2026-07-29",              // 面试日期
  "result": "未通过(一面)",          // 结果（可选）

  // —— 岗位JD（可选）——
  "jd": {
    "responsibilities": ["职责1", "职责2"],
    "requirements": ["要求1", "要求2"]
  },

  // —— 业务线（可选）——
  "business_line": "面试官所在业务线的描述（反问环节得知）",
  "match_hint": "候选人与该业务的匹配度提示",

  // —— 逐题复盘（核心）——
  "qa": [
    // ▶ 普通题（面试官问、你答）：type 缺省或 "normal"
    {
      "type": "normal",              // 可省略
      "no": "Q1",                    // 题号
      "time": "00:03-00:49",         // 时间点
      "module": "XX小程序",     // 所属模块/经历
      "q": "面试官问题（录音原话，清理口吃不概括）",
      "a": "我的回答（录音原话）",
      "eval": "🔴 问题。具体点评...",
      "better": "改进版回答（按总-分-果重写）",
      "gain": "提升点：改进版相比原回答提升了什么（可迁移技巧）"
    },

    // ▶ 反问环节题（你问、面试官答）：type: "reverse"
    // q 是"我的提问"，a 是"面试官回答"，评价分两侧
    {
      "type": "reverse",
      "no": "Q11",                   // 题号（建议反问环节单独连续编号或标 R1/R2）
      "time": "28:21-29:00",
      "module": "反问·产出预期",
      "q": "我的提问（原话，清理口吃）",
      "a": "面试官的回答（原话）",
      "q_eval": "✅ 好。对这个提问的评价——问得好不好、得不得体、深不深",
      "q_better": "这个提问怎么问更好（改进版提问）",
      "q_gain": "提问提升点：反问技巧的可迁移心得（如『问产出预期』比『问我不足』高级在哪）",
      "a_eval": "面试官回答透露的信息分析——对岗位/候选人/文化的信号，原话里藏的态度",
      "a_gain": "回答启示：这条反馈对候选人有什么用、要怎么跟进"
    }
  ],

  // —— 反馈与结论（可选）——
  "interviewer_feedback": "面试官原话反馈（可直接引用）",
  "conclusions": [
    ["核心问题", "本场最突出的短板"],
    ["改进方向", "针对核心问题的可执行改进"]
  ]
}
```

## 字段优先级

- **必填**：`candidate`、`company`、`position`、`date`、`qa`
- **强烈建议**：`result`、`type`（区分普通题/反问题）、`eval`（每题）、`better`（每题）、`gain`（每题）、`conclusions`
- **可选**：`jd`、`business_line`、`match_hint`、`interviewer_feedback`
- **反问题专属**（type=reverse 时强烈建议）：`q_eval`、`q_better`、`q_gain`、`a_eval`、`a_gain`

## type 字段（区分两种题）

`qa` 数组里每条用 `type` 区分渲染方式：

| type | 谁问谁答 | 表格行数 | 字段含义 |
|------|---------|---------|---------|
| `"normal"`（缺省） | 面试官问 → 你答 | 5 行 | q=面试官问题, a=你的回答, eval/better/gain 评你的回答 |
| `"reverse"` | 你问 → 面试官答 | 7 行 | q=你的提问, a=面试官回答；q_eval/q_better/q_gain 评你的提问；a_eval/a_gain 析面试官回答 |

## eval 类字段的取值规范

所有 `*_eval` 字段（`eval`/`q_eval`/`a_eval`）必须以三档标记之一开头，便于一眼识别：

- `✅ 好。...` —— 达标/正向信号
- `🟡 可改进。...` —— 方向对但有短板/中性信号
- `🔴 问题。...` —— 明显减分/负向信号

判定标准见 `methodology.md`。

## 最小可用示例

```json
{
  "candidate": "张三",
  "round": 1,
  "company": "百度",
  "position": "产品经理",
  "date": "2026-07-29",
  "qa": [
    {
      "no": "Q1",
      "time": "00:03",
      "module": "项目",
      "q": "你的小程序网络失败，有做运营吗？",
      "a": "说实话这个只是为拿实习做的，后面没关注。",
      "eval": "🔴 问题。自我贬低，且暴露无运营。",
      "better": "这个项目验证想法后冷启动过一批用户，后续重心转到商用项目了。",
      "gain": "把「没关注」改成「重心转移」，不自我贬低。"
    },
    {
      "type": "reverse",
      "no": "R1",
      "time": "28:21",
      "module": "反问",
      "q": "您希望实习生在不同阶段有什么产出？",
      "a": "希望快速动手实操，要有独立思考，公司讲自由责任。",
      "q_eval": "✅ 好。问产出预期是请教练式提问，展示进取心。",
      "q_better": "（已达标。可追问：您说的动手实操是指搭建客户AI Demo吗？）",
      "q_gain": "反问问『产出预期/岗位要求』比问『我有什么不足』高级——前者请教练，后者甩压力。",
      "a_eval": "正向信号：三次提『动手/独立思考/创业精神』=岗位要的人；明确表达了对候选人的认可。",
      "a_gain": "这三条就是该岗的核心要求，备考和入职后都要对齐。"
    }
  ]
}
```
