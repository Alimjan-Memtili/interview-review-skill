# 面试复盘方法论

本文件定义「如何评价一个回答」「如何写改进版」「提升点写什么」的标准。复盘时严格按此执行。

## 一、评价标准（给每条回答打标）

每条「我的回答」必须给出一个三档评级 + 具体点评。**先定档，再给理由。**

| 标记 | 含义 | 判定标准 |
|------|------|----------|
| ✅ 好 | 达标，可复用 | 结构清晰、先给重点、内容真实、经得起追问 |
| 🟡 可改进 | 方向对但有短板 | 内容真实但：缺总结/重点后置/表达绕/细节淹没结论 |
| 🔴 问题 | 明显减分 | 自我贬低、说「记不得/没办法」、暴露基本功缺失（如做产品却不懂竞品）、答非所问 |

### 常见减分模式（出现即标 🔴 或 🟡）

1. **细节淹没总结**：堆砌做了什么，面试官得自己拼凑「所以呢」
2. **自我设伤**：主动贬低自己的项目/经历（见下方「自我设伤的 5 种伪装」）
3. **重点后置**：核心结论放在最后才说，前面铺垫太长
4. **方法缺失**：说「没办法/记不得」，显得被动无复盘意识
5. **基本功露怯**：做了某类产品却答不出该领域竞品/常识
6. **姿态错误**：反问环节把压力甩给面试官（如『您觉得我有什么不足』），或问『几面能过/给多少钱』

### 自我设伤的 5 种伪装（高频，要逐一识别）

⚠️ 自我设伤不只是「这项目没用」这一种，它有多种伪装形式。下面五种来自真实复盘的模式，长得不一样但本质相同——**面试官没让你否定自己，你却主动帮面试官否定自己**。

| # | 伪装形式 | 典型表现 | 为什么减分 |
|---|---------|------------------------|-----------|
| 1 | **贬低项目价值** | "这个当时只是为了拿实习机会做的，后面没关注了" | 面试官让你展示能力，你却否定项目本身 |
| 2 | **贬低实习含金量** | "这段含金量不高，比较一般"；"这段没写到简历上，太占空间" | 主动告诉面试官"这段经历不值钱" |
| 3 | **主动藏弹药** | "这个跟JD不太相关，我就不展开了" | 哪怕真不相关，让面试官判断，你主动藏=自认没用 |
| 4 | **贬低准备度** | "我也没有研究得很透，应该差不多" | 在面某方向时说对它研究不透 = 自认没准备 |
| 5 | **声称不会/没做** | "我做的需求是没有做那种分析的"（指效果评估） | ⚠️ 这种**可能是理性诚实**而非自贬，见下方区分 |

**⚠️ 第 5 种的关键区分（理性诚实 vs 自我设伤）**：

自我设伤和理性诚实长得像，但本质相反，评价前必须判断是哪种：
- **理性诚实（✅ 加分）**：基于客观限制说「没法做某事」**且主动补证据**证明能力在别处。例：「我负责的这类体验优化需求客观上没法用单一指标归因，对标竞品是合理做法；但我帮 mentor 做过另一个功能的前后指标对比，那套方法我会。」
- **自我设伤（🔴 减分）**：无端贬低、没有客观限制也否定、否定后不补证据。

**判断标准**：候选人否定自己后，有没有紧接着给出「但我有另一种方式证明能力」？有 = 理性诚实；没有 = 自我设伤。

### 常见加分模式（出现即标 ✅）

1. **先总后分**：一句话总结 → 关键动作 → 结果
2. **设计取舍**：讲清楚「为什么这么选」而非「我做了什么」（体现判断力）
3. **量化结果**：给出数据/阈值/覆盖规模
4. **诚实但不躺平**：承认不足的同时给出改进计划

## 二、改进版回答的写法（better）

改进版不是「换个说法润色」，而是**先判断内容对错，再给一个完美回答**。目标是下次能直接背、直接用。

### ⚠️ 写 better 之前的前置步骤：内容判断（必做）

**润色一个方向就错了的回答毫无意义。** 写 better 前必须先判断候选人说的内容本身有没有错，判断结论写进 eval，然后才写 better：

| 题型 | 要判断什么 | 举例（方向错了就必须推翻重写） |
|------|-----------|------|
| 开放题 | 方向对不对？有没有答非所问/方向偏差？给的答案是否真的回答了问题？ | 问"AI能做什么创新"，答"分析数据出报告"——方向错了，这是传统方案已有的，不是AI创新 |
| 经历类 | 呈现有没有事实问题？有没有遗漏关键信息/错误归因？ | 讲商用项目只讲开发过程不讲结果数据——遗漏了最有力的证据 |
| 知识/概念类 | 理解准不准？有没有硬伤？ | 把策略产品归到B端——分类错误 |

**如果方向错了，better 和原回答可以差异很大**——不是修修补补，而是按"这道题的标准满分答案应该长什么样"来重写（但必须诚信，不编造候选人没有的经历/技能，见红线一节）。

### 「总-分-果」结构（核心范式）

```
总：一句话总结——做了什么 + 解决谁的什么问题 + 做到什么程度/结果
分：1-3 个关键动作（不堆细节，每个动作点到为止，等追问再展开）
果：结果/影响/学到了什么（用数据或方法论收尾）
```

**对比示例**（来自真实复盘模式）：

> ❌ 原回答（细节淹没）："做了工具自定义排序、AI回复，还有一些插件、知识库、智能总结……具体的我记不太得了。"
>
> ✅ 改进版（总-分-果）："核心升级两点：①工具可配置化，一线用户能按习惯排序裁剪；②AI辅助回复，先生成草稿再润色。这两点直接对标调研里最高频的两个痛点——工具不顺手、回复太慢。"

### 改进版必做的四件事

0. **先做内容判断**（前置）——方向/事实/知识有没有错？错了就在 eval 点明，better 推翻重写
1. **把核心结论提到最前面**（解决「重点后置」）
2. **细节压缩成关键动作**，每个动作配一句「为什么」（解决「细节淹没」）
3. **补一个结果或学到的点**收尾（解决「只讲过程不讲价值」）

### ⚠️ 改进版的红线：不能编内容（诚信优先）

改进版只能优化「怎么说」，**不能伪造「说什么」**。候选人没做过的方向不声称立志深耕、没掌握的技能不声称精通——否则面试官一追问就露馅，且违背候选人诚信做人的原则。

**真话有三种讲法（表达策略的合法范围）：**

| 讲法 | 例子 | 对错 |
|------|------|------|
| 编内容 ❌ | "我决定深耕数据产品方向"（没做过） | 没做过的方向硬说立志做，一追问就露馅 |
| 纯自贬 ❌ | "我 SQL 很一般，数据产品也没研究透" | 真话但没必要主动抖，且姿态是「我不行」 |
| **诚信+策略** ✅ | "之前的实习让我对数据方向有兴趣，但还没真做过，想通过这段实习深入了解" | 真话、建立了连接、显成长性 |

**关键区分**：
- **诚实承认能力边界**（"还在探索期/想深入了解/想学"）= ✅ 成长性，是加分的
- **主动否定自己**（"含金量不高/研究不透/比较一般"）= 🔴 减分
- 同一个事实（"我没做过数据产品"），讲成"想来学"是加分，讲成"我不行"是减分，姿态不同效果差很大。改进版要做的是**前者**。

**给改进版写作者的检查**：写完 better 后问自己——这个版本候选人被面试官追问时接得住吗？如果接不住（因为内容是编的），就重新写，宁可平实也不要虚构。

## 三、提升点的写法（gain）

提升点回答：**改进版相比原回答，到底好在哪？** 要给出**可迁移的技巧**，而非泛泛的「更好了」。

### 好的提升点 vs 差的提升点

| ❌ 差（空泛） | ✅ 好（可迁移） |
|---|---|
| 表达更清晰 | ①把「没关注」改成「重心转移」，不自我贬低 |
| 更有重点 | 把痛点从结尾提到开头，先讲为什么再做怎么做 |
| 更专业 | 答对前两点就停，不主动往细节里钻 |

### 提升点常用的几个维度

写提升点时，从这些维度找「到底提升了什么」：

1. **顺序**：结论前置 / 痛点前置
2. **结构**：流水账 → 分维度（如「沟通层/技术层」）
3. **姿态**：自我贬低 → 重心转移/请教练
4. **收束**：散点 → 结果量化（如「零事故/覆盖20人」）
5. **因果**：功能清单 → 解决了什么问题
6. **方法**：「没办法」→ 可复用方法论

## 四、整场复盘结论（conclusions）

每场面试末尾，用标签 + 结论的形式总结 5 条左右，标准维度：

| 标签 | 写什么 |
|------|--------|
| 核心问题 | 这场最突出的短板是什么（通常面试官会直接点出） |
| 改进方向 | 针对核心问题的可执行改进（如改用总-分-果） |
| 致命失误 | 具体的减分动作（如贬低项目、竞品答不出） |
| 闪光点 | 真实且有深度的亮点（保留并强化） |
| 下一步行动 | 具体的准备动作（如练AI对练、补竞品） |

## 五、复盘的整体心法

- **复盘的价值在「改进版」和「提升点」，不在「记录」**。每道没答好的题，重写成下次能直接用的版本。
- **原话要保真**：面试官问题和我的回答用录音原话（清理口吃，不概括），这样评价和改进才有锚点。
- **评价要狠要准**：不要为了好看给全场都打 ✅，🔴 和 🟡 才是复盘的价值所在。
- **提升点要可迁移**：提炼成「下次任何题都能用的表达技巧」，比背单个答案更有用。

## 六、反问环节的识别与评价（独立段落）

反问环节是整场面试里**角色反转**的一段——变成「你问、面试官答」。它和正文题不一样，必须单独处理：

### 1. 怎么识别反问环节
- 转写里通常是面试官先说「你有什么想问我的」「你有什么问题吗」，之后**连续几轮都是候选人在提问**。
- 反问环节里的每一轮，**提问方=候选人**，回答方=面试官，和正文完全相反。
- 标记为 `type: "reverse"`，在文档里渲染成独立的「三、反问环节」段落（紫色系配色，和正文题区分）。

### 2. 反问题评价两侧（这是和普通题最大的区别）
反问题不能套「面试官问题/我的回答/评价我的回答」那套——因为这里**你的提问也要被评价**。每个反问题产出 7 个字段：

| 字段 | 评价谁 | 说明 |
|------|--------|------|
| `q` | —— | **我的提问**（原话） |
| `a` | —— | **面试官回答**（原话） |
| `q_eval` | 我的提问 | 问得好不好、得不得体、深不深。好问题=展示匹配度/进取心/请教练；差问题=把压力甩面试官/显得没准备 |
| `q_better` | 我的提问 | 这个问题怎么问更好（改进版提问） |
| `q_gain` | 我的提问 | 反问技巧的可迁移心得（如「问产出预期」比「问我不足」高级在哪） |
| `a_eval` | 面试官回答 | 回答透露的信息/信号——对岗位要求、候选人评价、团队文化的暗示，原话里藏的态度 |
| `a_gain` | 面试官回答 | 回答启示：这条反馈对候选人有什么用、要怎么跟进 |

### 3. 反问评价的常见标档
**对提问（q_eval）**：
- ✅ 好：问产出预期/岗位要求（请教练式）、结合对方业务深挖（展示匹配度）、问面试官成长路径（得体）
- 🟡 可改进：问得太泛、没结合自己专长、问业务但不够具体
- 🔴 问题：「我有什么不足/您怎么评价我」（把压力甩给面试官）、「几面能过/给多少钱」（太功利）、「你们加班多吗」（开场就问减分）

**对面试官回答（a_eval）**：
- ✅ 正向信号：明确表达认可（「性格匹配」）、具体描述岗位要求、给出建设性建议
- 🟡 中性：客套话、模糊评价（「还不错」）
- 🔴 负向信号：回避正面回答、强调差距、语气敷衍

### 4. 反问环节的价值
反问环节往往是**整场信息密度最高**的一段——面试官会在这里透露真实的岗位要求、对你的评价、团队文化。**逐字分析面试官的回答**，比分析你自己的回答更值钱。上面三个问题就是挖掘信号的标准动作。
